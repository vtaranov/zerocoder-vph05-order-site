# VPh05 - сайт обработки заявок Atelier

Учебная работа Виктора Таранова. Продолжение [инфраструктуры VPh04](https://github.com/vtaranov/zerocoder-vph04-order-infrastructure): FastAPI, PostgreSQL и сайт автомобильного ателье в светлой теме. Услуги и диапазоны цен загружаются из базы, форма сохраняет заявку и её метрики одной транзакцией.

## Возможности

- Адаптивная страница с округлой типографикой, спокойной анимацией и поддержкой `prefers-reduced-motion`.
- Динамический каталог услуг и ползунок бюджета в пределах выбранной услуги.
- Контакты, удобное время и способ связи, пожелания, срок, необязательные сведения о компании, роли и объёме задачи.
- Метрики: время на странице, число посещений в этом браузере, до 100 меток кликов, до 60 координат курсора и параметры браузера. Координаты - разреженные точки, а не полноценная карта наведения. При недоступном localStorage форма продолжает работать.
- Данные отправляются только с согласием вместе с заявкой. Метрики собираются в памяти страницы; счётчик посещений хранится в localStorage. Сторонней аналитики, CDN и внешних шрифтов нет. Swagger JS/CSS также обслуживаются локально.
- Swagger `/docs`: создание, чтение, изменение и удаление услуг; чтение/удаление заявок и просмотр их метрик.
- HTTP Basic для административных операций поверх HTTPS. Каталог и отправка заявки публичны, заявки и метрики доступны администратору.

## Архитектура

Браузер → HTTPS Nginx → `/api/*` FastAPI → PostgreSQL. Nginx отдаёт собранную статику. Backend и PostgreSQL не публикуют порты хоста и находятся во внутренней сети Docker. В Compose БД называется `postgres` (это `db` из формулировки задания).

Сохранены pgAdmin `/pgadmin/`, Registry `/v2/` и Watchtower из VPh04. Три прикладные таблицы: `services`, `applications`, `behavior_metrics`. Метрики связаны с заявкой один к одному общим PK/FK; при удалении заявки каскадно удаляются. Нельзя удалить услугу с существующими заявками. SQL-структуры описаны в docstring моделей, операции - в классах CRUD рядом с моделями, маршруты - отдельно, драйвер БД - в `core`.

Внешний порт по умолчанию **18443**. Системный Nginx других приложений может продолжать занимать 80/443.

## Запуск с нуля

Требования: Linux VPS, Docker Engine и Compose, действительный TLS-сертификат, Node.js 24+ для сборки фронтенда, Python 3 для генерации конфигурации. Backend запускается в Python 3.13 внутри контейнера. Установку отсутствующих инструментов согласуйте с администратором.

```sh
git clone https://github.com/vtaranov/zerocoder-vph05-order-site.git
cd zerocoder-vph05-order-site
python3 scripts/init-secrets.py --host your-server.example.com --email admin@example.com
```

Скрипт создаёт `.env` с независимыми случайными паролями. Проверьте пути TLS, порт и параметры БД; при изменении БД/пользователя обновите `pgadmin/servers.json`. Монтируются оба каталога Certbot `live` и `archive`, чтобы сохранить символьные ссылки сертификата. Подготовка TLS выполняется администратором до запуска; не отключайте проверку сертификата.

```sh
cd frontend
npm ci
npm run build
cd ..
mkdir -p web
cp -R frontend/dist/. web/
./registry/create-user.sh vph04
docker compose -f docker-compose.yml -f compose.lock.yml up -d --build --wait --wait-timeout 180
```

Сборщик фронтенда использует Node.js standard library. Единственная npm-зависимость - зафиксированный `swagger-ui-dist` для локального интерфейса Swagger; `npm ci` устанавливает её по lock-файлу. `npm run build` создаёт HTML и CSS/JS с хешами имён в `frontend/dist`, а также копирует файлы Swagger в `backend/app/static`. Следует копировать результат в `web`, который смонтирован в Nginx. `compose.lock.yml` фиксирует пять инфраструктурных образов по digest. Backend собирается из `backend/Dockerfile`; прямые зависимости зафиксированы в `requirements.txt`, полное проверенное окружение разработчика - в `requirements-lock.txt`.

Откройте `https://your-server.example.com:18443/`, Swagger - `/docs`. В Swagger нажмите **Authorize**: логин `admin`, пароль `ADMIN_PASSWORD` из `.env`. Новый сервер начинает с пустого каталога. Создайте минимум три услуги через **POST /api/admin/services → Try it out → Execute**, например:

```json
{"name":"Полировка", "description":"Восстановление блеска и глубины цвета", "budget_min":15000, "budget_max":45000}
```

| Услуга | Минимальный бюджет | Максимальный бюджет |
|---|---:|---:|
| Полировка | 15 000 ₽ | 45 000 ₽ |
| Химчистка | 8 000 ₽ | 25 000 ₽ |
| Керамика | 30 000 ₽ | 90 000 ₽ |

Проверьте **GET /api/services**, затем обновите главную, выберите услугу, заполните форму и отправьте заявку. Сообщение успеха: **«Заявка отправлена!»**, затем номер. Проверьте запись через защищённый **GET /api/admin/applications** или pgAdmin. `/api/health` возвращает состояние БД.

## Продолжение развёрнутого VPh04

Сохраните копии конфигурации, `.env`, `web` и дамп PostgreSQL до изменений. При запуске из прежнего каталога с прежним `COMPOSE_PROJECT_NAME=vph04` используются существующие тома. Не запускайте второй экземпляр с теми же портами. Дополните прежний `.env` новым случайным `ADMIN_PASSWORD`, перенесите backend, Compose, Nginx и собранный `web`, запустите backend и перезапустите учебный Nginx.

Новый локальный образ `vph05-backend:1.0` намеренно не помечен для Watchtower: обновление выполняется командой Compose. Свой Registry сохранён для следующих упражнений; автоматическая доставка backend в него этим ДЗ не реализована. Watchtower продолжает выбирать только явно помеченные контейнеры scope `vph04`.

## API

| Метод и путь | Доступ | Назначение |
|---|---|---|
| GET `/api/services` | Публичный | Каталог услуг |
| POST `/api/applications` | Публичный | Сохранение заявки и метрик |
| POST `/api/admin/services` | Администратор | Создать услугу |
| PUT/DELETE `/api/admin/services/{id}` | Администратор | Изменить/удалить услугу |
| GET `/api/admin/applications` | Администратор | Список заявок |
| DELETE `/api/admin/applications/{id}` | Администратор | Удалить заявку и метрики |
| GET `/api/admin/applications/{id}/metrics` | Администратор | Метрики заявки |

Маршруты используются без завершающего `/`, поэтому штатная отправка формы не требует 307-редиректа. Nginx передаёт `/api/` без изменения пути. Максимальный размер JSON на входе - 32 КБ. Валидация сервера проверяет услугу, бюджет, длины строк и согласие; ошибки возвращают 422, дубли услуг и удаление используемой услуги - 409. Отправка не очищает форму при ошибке.

## Проверки и диагностика

Для локального API-теста нужен отдельный Python 3.13 venv:

```sh
(cd frontend && npm ci && npm run build)
python3.13 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd backend
PYTHONPATH=. ../.venv/bin/python -m pytest -q
```

Локальный тест подменяет PostgreSQL временной SQLite в памяти с включёнными foreign keys. Он проверяет авторизацию, валидацию, отсутствие частичных записей при неверных данных, связь заявки с метриками и каскадное удаление. Это не заменяет проверку PostgreSQL на сервере. GitHub Actions запускает тот же тест и сборку фронтенда.

```sh
docker compose ps
docker compose logs --tail=100 backend
docker compose logs -f backend
docker compose exec -T nginx nginx -t
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT id, service_id, budget FROM applications;"'
```

Секреты, заявки, дампы, протоколы и снимки не публикуются в репозитории. Пароли нужно хранить отдельно. При обновлении зависимостей повторите тесты и сборку.

## Сохранность и ограничения

PostgreSQL использует постоянный том. Не применяйте `docker compose down -v` для обычной остановки. Резервная копия:

```sh
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > orders.sql
```

Храните дамп вне публичного репозитория и VPS. Для восстановления инфраструктуры см. README VPh04. Hook `scripts/reload-tls.sh` рассчитан на прежний путь `/opt/vph04-orders`.

Это учебный сервис: нет рассылки клиентам, CRM-воронки, JWT-панели, внешнего резервирования и защиты от массовой отправки заявок. Basic Auth подходит для ограниченного учебного доступа; перед эксплуатацией с реальными клиентами нужно определить политику хранения данных, доступ, ограничения запросов и процесс резервирования. Схема создаётся при старте через `create_all`; изменения существующих колонок требуют отдельной миграции.
